# سجل تنفيذ مشروع Thanaweya — المرحلة الأولى

**الحالة:** دفعة تأسيس الجودة والنزاهة قيد المراجعة، وليست إصداراً نهائياً.
**الفرع:** `manus/quality-foundation`، مبني على `dccacdc` من مستودع `abueid201224/thanawaya`.
**الهدف:** تحسين موثوقية التقييم، سلامة حساب الطالب، وتجربة بدء التطبيق، قبل توسيع المحتوى أو نشر نسخة Windows.

## ما نُفّذ في هذه الدفعة

- إصلاح توافق `package.json` مع `package-lock.json` وإتاحة تثبيت نظيف باستخدام `npm ci`.
- إضافة أمر اختبار واضح يجمع فحوص TypeScript واختبارات وحدات. أضيفت قواعد حتمية لحساب درجات الامتحان، ومعالجة الدرجة صفر والاختبار الخالي من الأسئلة، ومنع اعتماد تخطي وحدة دون مخطط تقييم مُراجع.
- إرجاع حالة الطالب الجديد إلى نقطة بداية حقيقية: لا وحدات مكتملة، ولا امتحانات أو درجات أو شارات أو سلسلة دراسة مزروعة، ولا هوية افتراضية بصلاحية مشرف.
- إزالة مسارات واجهة تمنح دور المشرف محلياً، وإيقاف منح الصلاحية اعتماداً على البريد. أضيف ترحيل Supabase لتقوية التحقق من الدور ومقاييس التقدم؛ منح المشرف أصبح يدوياً بمعرّف Auth UUID بعد التحقق من المالك.
- جعل خدمة الاختبارات في WPF ترفض مخرجات التوليد الناقصة أو غير الصالحة، ومنع منح درجة أو أسئلة احتياطية توحي بنجاح غير حقيقي عند غياب خدمة الذكاء الاصطناعي. أضيفت اختبارات تحقق لهذا السلوك، وأصبح مفتاح Gemini يُرسل في الترويسة لا في URL. وُضعت حدود لنوع/حجم صورة الإجابة؛ ومخرجات التصحيح توصف بأنها استرشادية وتحتاج مراجعة بشرية.
- توضيح أن أمثلة المقال وOCR الثابتة أمثلة تعليمية وليست تصحيحاً أو قراءة صورة أو نموذج إجابة رسمياً؛ أزيلت صور الإنترنت ونسب الثقة المختلقة، وصُحح إرسال نوع الصورة الفعلي إلى خدمة OCR.
- تحميل صفحات التطبيق والنوافذ ومكتبات PDF عند الحاجة بدلاً من تضمينها كلها في الدفعة الأولى.
- إعادة تنظيم GitHub Actions بحيث تكون فحوص PR للقراءة فقط، ويُبنى مثبت Windows ويُفحص على `windows-latest` لكل PR، ويُقيّد نشر أصول الإصدار بصلاحية كتابة منفصلة. يمنع أمر التغليف المحلي النشر التلقائي.
- ترحيل عميل WPF إلى Supabase C# SDK 8.8.0 وتكييف namespaces وواجهات الجداول مع الإصدار المدعوم؛ المراجع: [NuGet](https://www.nuget.org/packages/Supabase/8.8.0)، [ملاحظات إصدار C#](https://supabase.com/docs/reference/csharp/release-notes)، [دليل ترحيل v8](https://github.com/supabase/supabase-csharp/blob/master/docs/migrations/v8.0.0.md).
- إصلاح بناء WPF: استبدال خصائص `StackPanel.Spacing` غير المدعومة بهوامش، وتصحيح تواقيع `AsyncRelayCommand` وتحويل نتائج استعلام Supabase.
- استكمال `package-lock.json` بـ62 حزمة native اختيارية لإصدارات Windows وبقية المنصات المطابقة للإصدارات المسجلة، بعد أن كشف CI أن lockfile المولّد على Linux أغفل اعتماديات TypeScript وVite/Tailwind الاختيارية الخاصة بـWindows.
- إزالة macro رمز النشر من `electron-builder.yml`؛ البناء مع `--publish never` لا يحتاج اعتماد نشر، ويُمرر `GH_TOKEN` فقط عند النشر اليدوي. يتوافق ذلك مع [دليل electron-builder v26 للنشر](https://www.electron.build/v26/docs/publish/) و[دليل GitHub Actions](https://www.electron.build/v26/docs/features/github-actions).

## نتائج التحقق المحلي

| الفحص | النتيجة |
|---|---|
| `npm ci --no-audit --no-fund` | نجح على تثبيت نظيف بعد إدراج ملفات المنصات الاختيارية دون تغيير إصدارات الاعتماديات الأساسية |
| `npm test` | نجحت فحوص TypeScript واختبارات الوحدات السبعة (7/7) |
| `npm run build:all` | نجح بناء الواجهة وعمليتي Electron على Linux |
| `node scripts/verify-build.mjs` | نجحت جميع بوابات الثوابت والأمان (36 تحققاً) |
| `git diff --check` | لا توجد أخطاء مسافات أو علامات تعارض |

بعد تقسيم التحميل، أصبح مدخل الواجهة نحو 525 كيلوبايت خاماً (نحو 152 كيلوبايت مضغوطاً وفق خرج Vite)، بدلاً من نحو 1.59 ميغابايت خاماً قبل فصل الصفحات والنوافذ. ما زال هناك تحذير Vite طفيف لتجاوز chunk الرئيسي حد 500 كيلوبايت؛ لا يمنع البناء، ويُسجّل للتحسين لاحقاً.

## حدود مهمة لم تُختبر بعد

- اجتاز Windows CI على commit `07cb62d` جميع اختبارات .NET وTypeScript والبناء وفحوص الأمان، ثم أنشأ المثبت ونسخة portable وفحصهما ورفعهما. artifact `ThanaweyaAmmaMathCopilot-Windows-x64` حجمه 208,734,550 بايت، والملفات متاحة لمدة 14 يوماً عبر [تشغيل CI رقم 41799200578](https://github.com/abueid201224/thanawaya/actions/runs/41799200578). النشر العام تخطّاه workflow عمداً.
- لم تُطبّق ترحيلات SQL على مشروع Supabase حي أو تجريبي، ولم يُجر اختبار RLS بمستخدم طالب ومشرف فعليين.
- لم تُختبر طلبات Gemini/OCR بمفتاح API أو خدمة خارجية. نجاح البناء لا يثبت صحة مخرجات النموذج.
- لم تُراجع بعد كل مادة وكل سؤال مقابل كتاب الوزارة أو مواصفة امتحان السنة الدراسية المستهدفة. لذلك لا ينبغي وصف بنك الأسئلة أو قواعد OCR الحالية بأنها معتمدة وزارياً.
- هذه دفعة تأسيسية وليست اعتماداً أمنياً أو تربوياً نهائياً. لم يُشغّل المثبت تفاعلياً على جهاز طالب، ولم يُختبر توقيع البرنامج أو SmartScreen أو التحديث التلقائي؛ يلزم اختبار قارئ شاشة/تكبير/RTL قبل الإصدار العام.

## مراحل التنفيذ التالية

1. **اختبار Windows اليدوي:** تنزيل artifact من تشغيل CI، تثبيت NSIS وتشغيل portable على جهاز Windows نظيف، وفحص RTL والخطوط الرياضية والعمل دون اتصال. لا إصدار عام قبل تحديد حالة التوقيع والتحديثات ومراجعة المالك.
2. **تدقيق المنهج:** تحديد السنة الدراسية، بناء مصفوفة تغطية مادة/وحدة/نواتج تعلم/أنماط أسئلة، ومراجعة كل حقيقة ومثال ومفتاح إجابة بمصدر رسمي وتاريخ إصدار ومراجع ثانٍ.
3. **التقييم التعليمي:** إنشاء بنك أسئلة مُراجع، مفاتيح إجابة قابلة للتحقق، تدرج تلميحات واسترجاع نشط، تحليل الأخطاء الشائعة، ومحاولات تدريب لا تكشف الحل قبل المحاولة. لا يعتمد تخطي وحدة أو درجة آلية على نسبة نجاح مجردة.
4. **الاستمرارية والخصوصية:** رسم حدود البيانات بين التخزين المحلي/غير المتصل وSupabase؛ اختبار سياسات RLS في بيئة staging، والتعامل الصريح مع التعارض والمزامنة والنسخ الاحتياطي وحذف بيانات الطالب.
5. **تجربة Windows:** اختبار RTL والخطوط الرياضية والطباعة والعمل دون اتصال، حالات الشبكة البطيئة، لوحة المفاتيح وقارئات الشاشة، ثم توقيع المثبت والتحديثات قبل الإصدار العام.
6. **تجربة طلاب ومراجعين:** تجربة محدودة بموافقة مدرسين وطلاب، جمع ملاحظات قابلة للقياس، ثم تعديل الخطة قبل توسيع النشر.

## بوابة النشر

لم يُدمج شيء في `main` ولم تُطبّق migrations على خدمة حيّة. تُراجع هذه الدفعة أولاً؛ وبعد اكتمال CI واختبار staging، تُحدّد مراجعة المالك قبل أي دمج أو إصدار عام.

## شريحة المرحلة الثانية — حالة مراجعة الأسئلة ووضوحها للطالب — 8 نوفمبر 2026

- أُجريت ثلاث مراجعات مستقلة لبنية بنك الأسئلة، وسلامة منطق التقييم، وخطة اختبار Windows. اتفقت المراجعات على عدم جواز ربط محتوى موجود بمنهج 2026/2027 أو اعتباره صحيحاً/مرخصاً قبل توفر وثيقة المنهج وإحالات دقيقة ومراجعة تربوية.
- أضيف `reviewStatus` إلزامي إلى `PracticeQuestion`، ووسمت الأسئلة الابتدائية الـ14 في وحدات التدريب والامتحانات الشهرية كلها بأنها `unreviewed`. الاختبار الجديد يتحقق من كل الأسئلة ومن عدم تفعيل `skipAssessmentReady` لأي وحدة ابتدائية.
- أصبحت حالة السؤال ونسبة المصدر النصية غير المحققة ظاهرتين في مستكشف التدريب. أزيل من التسميات ما أوحى بأسئلة امتحانات سابقة مثبتة أو بامتحان وزاري/موحد، وصُحح وصف التوقيت وتغطية المنهج وضمان الدرجة إلى بيان صريح بأن هذه عينات تدريب غير مراجعة.
- **التحقق المحلي لهذه الشريحة:** `npm test` نجح (**10/10** اختبارات) متضمناً فحوص TypeScript؛ `npm run build:all` نجح لبناء React وعمليتي Electron على Linux؛ واجتاز `node scripts/verify-build.mjs` فحوص الثوابت الأمنية والبنائية، واجتاز فحص `git diff --check` مع تفسير CRLF كنهاية سطر. بقي تحذير Vite المعروف بشأن chunk يتجاوز 500 كيلوبايت.
- **Windows CI للشريحة الأولى:** اجتاز commit `f5f501a` اختبارات .NET وTypeScript والبناء وفحوص الأمان وتغليف Windows والتحقق من الأرشيف في [التشغيل 42460141965](https://github.com/abueid201224/thanawaya/actions/runs/42460141965). رُفع `thanaweya-compiled-app` (2,973,362 بايت) و`ThanaweyaAmmaMathCopilot-Windows-x64` (208,729,599 بايت)؛ وتخطّى workflow النشر العام عمداً لأن PR ما زال مسودة. لا تتوفر `dotnet` محلياً على Linux. سجّل CI تحذيرات غير مانعة عن تقادم Node.js 20 في بعض Actions وتحذيرات nullable في WPF. حالة `unreviewed` لا تثبت صحة المفتاح أو الشرح أو حقوق الاستخدام، ولا تحل محل مراجعة مدرس.

### بوابات العمل التالية

1. **بوابة التخطي:** في شريحة المتابعة المحلية أضيف شرط مراجعة كل سؤال ومطابقته نصياً مع كل ناتج تعلم قبل استخدام نتيجة التخطي، وأزيلت الزيادة الثابتة (+3) في عداد الإتقان. يظل ذلك بحاجة إلى اختبار Windows CI ومراجعة الخريطة الفعلية قبل تفعيل أي وحدة.
2. إضافة بيانات provenance لكل سؤال (معرّف المرجع، الورقة/الصفحة، الإصدار والسنة، النطاق المنهجي، حالة الحقوق والمراجع وتاريخ المراجعة) عندما تتوفر أدلة فعلية؛ لا تُستنتج هذه القيم من `examSource` النصي.
3. لا تبدأ مطابقة مواد 2026/2027 قبل تسليم كتاب أو نشرة رسمية تحدد السنة والصف والشعبة والمادة. بعد توفرها تُبنى خريطة معرفات نواتج التعلم وتُراجع الأسئلة والمفاتيح والحلول على يد مدرسين.
4. اختبار مسار التخزين المحلي الاحتياطي بوحدات مستقلة، ثم اختبار تثبيت وتشغيل التطبيق وRTL والخطوط والمعادلات على Windows فعلي قبل أي إصدار عام.
